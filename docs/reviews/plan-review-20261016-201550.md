## Mandatory lenses

- Goal-bound minimal design：每项输出均对应用户确认范围；测试为现有行为证据，不增加产品目标。
- Architecture boundary：文档描述 CLI/MCP 真实复用关系和模块所有者；无代码层间改造。
- Best practice：以配置默认值、源码分支、测试优先于 README；明确 mock 与真实环境边界。
- Optimal solution：仓库原生 Markdown/Mermaid 比新增文档站点更便于同 PR 审查。
- Overengineering：不做未授权架构重构、KPI 目标设定、业务修复；单 slice。
- Overcoupling：文档以链接引用真源，不复制运行时规则为第二套可执行配置；符号链接比固定行号更适合长期维护。
- Execution / failure / recovery：计划覆盖部分采集、快照与数据库不同事务、模型失效、并发和缓存丢失的限制；不把这些限制当已修复能力。
