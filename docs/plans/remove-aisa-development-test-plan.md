# remove-aisa 开发与测试计划

日期：2026-10-17。分支：`remove-aisa`。起点：`dd4ff77`（已修复X批处理超时风险）。
本文件描述待开发方案，不代表实现或验收已完成。
验收依据：[AIsa全功能替换标准](aisa-replacement-acceptance.md)。
机器可读覆盖登记：[capability manifest](remove-aisa-capabilities.json)。

## 1. 目标与范围

完整替代AIsa提供的全部13类能力，保留X账号监听和关键词搜索。生产路径不依赖AIsa Key、域名、工具路由或间接代理。
尽量使用免费额度和低成本服务，但不能关闭功能、漏采、用模型猜测市场数据或只提供人工CSV来获得“全功能完成”。
保留现有CLI、stdio MCP、Windows Git Bash和Linux Bash启动方式，配置与凭据只读本地JSON，不用环境变量或用户CLI登录回退。
原有日报、历史快照、线索数据库和14天复盘继续有效。原独立来源GitHub/HF/Sitemap/GSC/GoAnyAPI/TrustMRR/邮件不得回归。

非目标：重做界面、引入网页服务、扩大监听账号、构建自营全网爬虫、绕过访问限制、自动充值或自动发送外部消息。
现有早晚任务先保持原配置；计划、开发、影子验收均不自动切换正式任务。

## 2. 直接代码依据

- `radar/aisa.py` 混合chat、批量工具路由和AisaError，是当前统一依赖。
- `sources.py`、`usecases.py`直接使用AIsa读取X，替换必须覆盖监听和关键词证据两个入口。
- `judge.py`、`usecases.py`、`asks.py`、`pains.py`都有模型调用，不能只改名字判断。
- `social.py`封装Reddit和YouTube评论；`review.py`依赖趋势；`new_sites.py`依赖域名与自然排名综合查询。
- `competition.py`通过AIsa取Google首页和KD，域名评级/供给数据则来自独立GoAnyAPI。
- `launcher.py`当前无条件要求AIsa Key；`config.py`对credentials/services有固定字段校验，`settings.py`使用ContextVar传递配置。
- `mcp_server.py`既调用关键词研究又运行整个采集；只改CLI会遗漏MCP路径。
- 现有完整回归曾113项通过，仅为旧逻辑基线，不能当作替换验证结果。

## 3. 技术方案与选型门

### 3.1 模型

首选直连DeepSeek官方API，模型名由本地文件配置。保留现有任务prompt和解析行为，先测基线再做必要校准。
统一`llm.chat(task, system, user, max_tokens)`，task映射名字判断、用途提炼、用途筛选、需求分类和痛点聚类。
适配器返回文本及实际usage/计费状态，业务模块不依赖供应商异常类型。
不要求逐字相同，但人工标注保留集上的质量必须达标。

### 3.2 X

首测TwitterAPIs，TwitterAPI.io作为质量/计费对照；在实际覆盖、字段、新鲜度和费用达标前不锁定主供应商。
两项必需操作：`user_posts(account, cursor/window)`与`search_posts(query, sort, cursor/window)`。
统一帖子ID、账号、正文、发布时间、互动、原始链接与分页信息；转推/引用/回复的识别在适配层保留。
保留逐账号请求和进度输出；不盲目重试计费请求。需要翻页时在预算内读完指定窗口，未读完标partial。
不把空结果等同账号不发帖；能区分有效空页、限流、未授权、上游错误及缺字段。

### 3.3 搜索量、趋势、Google首页、KD与新站

优先验证直连DataForSEO能否访问原来使用的同上游数据：历史月量、Trends、Google organic SERP、Labs KD、Domains WHOIS Overview。
这是数据口径兼容性优先方案，不预先声称直接采购一定更便宜，也不预先承诺接口资格或最小充值。
通过价格/最低消费/访问资格核验和小样本试验后再选择；预算上限不适合时比较其他合法来源。
SERP/Trends可比较SerpApi、Serper、GoAnyAPI；但替代源必须满足缺失字段、地区、粒度、联合曲线及归一化要求。
月量不能用Suggest补；KD不能用LLM补；新站不能用单个域名RDAP查询补。CSV仅用于交叉核验或暂时降级。
同上游响应可以保持原有归一化与决策函数；新指标需独立字段/版本及阈值校准，不能沿用旧阈值假装同指标。
若任务式API是必要方案，适配器内部做有时限的提交/轮询；报表保留pending状态，重跑复用任务ID，不重复购买任务。

### 3.4 Reddit与YouTube

Reddit先验证官方API权限和搜索结果是否覆盖所需查询/正文；无法满足时选合法第三方，不能以摘要代正文。
YouTube先验证官方Data API的commentThreads与点赞字段，覆盖原顶层评论语义；不扩大为读取所有回复。
免费配额是否足够应记录实测，关闭评论、无权限与无评论必须分开。
需求分类和聚类走DeepSeek；Chrome评价、视频发现等已有GoAnyAPI路径继续回归。

### 3.5 S0必须解决的阻塞项

- 选定X供应商的账号/关键词两类接口、免费测试额度和真实单位成本。
- 月量、KD、新域名发现的有效服务来源和账户资格；不能仅完成其他10项就宣布完工。
- Reddit合法访问权限及正文覆盖；YouTube项目/API Key与免费配额。
- 测试预算上限、长期月预算、对照样本保存许可及旧AIsa基线取得方式。
- 冻结验收标准的数值门槛；测试后不得为通过而改低。

无凭据时继续开发离线适配和测试，但真实验收标BLOCKED。不得伪造真实服务成功记录。

## 4. 最小架构、配置与数据契约

建议新增`radar/providers/`下的`contracts.py`、`errors.py`及按能力组织的`llm.py`、`x.py`、`seo.py`、`social.py`。
只实现选定供应商，不先造动态插件框架、继承树或任意URL代理系统。统一接口返回普通可序列化记录，业务模块依赖能力而非供应商工具名。

通用结果包含：provider、operation、status、data、country/language、time_range、fetched_at、cache信息、usage和cost。
status最少区分ok、empty、no_data、partial、error、quota_exhausted和pending；可选功能显式disabled。
金额统一整数微美元；unknown费用用null及原因，不当成0；配额单位和货币金额分开。
供应商原始cursor不能跨服务使用；稳定ID/业务实体ID可复用。快照增加来源与schema版本，转换必须可回滚。

本地`config.json`新增schema版本和providers配置；示例仅用占位Key。沿用ContextVar和线程上下文继承，重载配置不保留旧密钥。
配置只允许支持的provider/字段，错误信息不回显密钥或错误填写成字段名的秘密。
旧aisa_api_key和AIsa地址应被识别为需迁移且禁止执行，不转发、不静默映射为DeepSeek Key。
迁移工具未来建议`python -m radar migrate-config --dry-run`，真实迁移需显式执行，先生成备份，不覆盖用户原文件。
该命令和下面新增测试命令目前均未实现。

仅启用命令所需的凭据；完整模式check必须列出所有必需能力是否可用；缺少其中一项不得误报完整模式可用。
`leads`等本地只读命令无需任何网络Key。DeepSeek选题单项可独立运行，但不等于完整模式通过。

## 5. 缓存、额度与失败策略

用现有state中的独立SQLite表/库记录usage与预算预留，事务防止并发和进程重启绕过限额；不得复用业务表含义。
缓存键包含provider、操作、查询、地区语言、时间窗口、分页和相关版本；模型缓存还含输入hash、模型和prompt版本。
X使用稳定帖子ID去重和明确高水位，不只按过期TTL跳过读取；低频轮询若超出一页必须补分页或标未完整。
日报频率、窗口和阈值不因降本私自改变。免费额度和试用优惠与常规成本分别记录。
默认不对可能已经计费的调用自动重试；重试/异步轮询策略逐接口确定并记账，不自动跨供应商回退。
额度预判失败或供应商余额不明时不保证硬金额上限；若用户要求硬上限，须供应商限制配合才允许上线。
上游请求不能并发写同一生产state；新增进程锁或任务排他需覆盖CLI与MCP。

## 6. 阶段与可交付切片

### S0：范围、选型与验收冻结

交付：13项覆盖表、候选来源可行性记录、基线commit/样本索引、冻结阈值、测试费用上限。
验证：每项能力都有来源、字段映射和实测路径；上游不可用项有明确BLOCKED记录。
出口：功能范围无缺口，关键服务资格和费用已确认。可离线准备，但不能跳过关键来源缺口进入“完整可用”状态。

### S1：独立模型和X发现链路

覆盖A01—A04：统一模型/X契约和本地配置接入，名字判断、X证据、用途筛选全部脱离AIsa。
交付：DeepSeek与选定X适配器、独立测试配置、字段与分页夹具、已知费用记录。
验证：契约/规则回归、无AIsa调用、X账号和搜索小样本对照、保留集模型初测；旧state副本可读取。
此阶段其他未替换能力应显示尚未迁移，绝不回退到旧AIsa。“部分完成”必须明确。

### S2：全数据与完整业务闭环

覆盖A05—A13：接入月量、联合趋势、首页、KD、新站、Reddit、YouTube，完成asks/pains/tutorials/review。
交付：可完整执行daily/sources/keywords/pains的替代数据链路，规范化结果、证据归因、缓存与累计预算。
验证：全能力契约夹具；同输入业务规则一致；故障、配额、重复执行、异步任务和价格未知测试；全部单项真实烟测。
缺失SEO字段的降级报告不能通过本阶段完整能力验收。

### S3：入口清理与切换候选

交付：启动器、CLI、MCP、样例配置、手册和定时任务模板统一迁移，生产调用链不再导入/使用AIsa模块。
旧AIsa基线实现从固定git提交运行在隔离测试环境，不作为生产可选provider保留。
验证：断网目标拦截、AIsa函数炸弹测试、实际DNS/HTTP外连审计和负例；Linux/Windows跨目录及含空格路径测试。
测试邮件使用替身，不向真实收件人发信；MCP stdout只能有协议内容，日志走stderr。

### S4：真实等效性、成本与持续观察

交付：同步A/B记录、人工标注评分、费用对账、7天14轮影子运行、真实14天复盘补验计划。
验证：满足验收文档全部质量门槛；按相同工作量核对成本，不将少读页数当成优化。
如真实14天尚未到期，离线时间推进可先通过，但完整验收中的该实测项仍NOT_RUN。

### S5：验收与正式迁移

交付：逐项PASS/FAIL/BLOCKED/NOT_RUN报告、配置迁移备份、状态兼容检查和回滚步骤。
验证：13项全部PASS、外连AIsa为0、历史状态无丢失、预算门通过；否则只能发布明确标注的部分实现。
正式切换前暂停旧写入任务、备份state、迁移配置、启动新版本烟测，再恢复计划任务，避免两版同时写入。
不自动推送/合并、不自动修改已运行的定时任务；最终部署切换另行确认。

## 7. 测试计划与覆盖要求

### T0 基线

固定`dd4ff77`及现有依赖，保存旧测试结果、契约样本、业务规则输出和成本口径。
真实AIsa对照不是必需每次重跑；优先用合法保存的既有样本，缺少的服务基线在预算获准后补采。
旧服务失败不能当质量真值；必要时使用同上游原始结果和独立核验，报告不同证据等级。

### T1 离线单元与契约

每个适配器覆盖成功、真实空、缺字段、类型错误、错误嵌套、400/401/402/429/504、超时、无效JSON与分页循环。
覆盖长帖、时区、Unicode、缺互动指标、删除项、重复ID、模型截断、坏JSON及token用量缺失。
使用构造夹具与获准脱敏真实样本；所有普通测试默认禁止外网，测试Key均为假值。

### T2 业务与状态回归

按A01—A13绑定固定输入和预期，覆盖首次/再次发现、已知词、阈值边界、品牌、优先级、竞争降级与复盘到期。
数据缺失必须null+原因，不是0。相同真实空输入才允许生成“无新增”。
覆盖配置重载、线程池和asyncio中的凭据上下文；历史state副本迁移、中断恢复、分页高水位与重复运行。

### T3 入口与零依赖

按CLI/启动器/MCP逐入口执行完整能力，不只跑帮助或预检。
移除AIsa Key，猴子补丁禁止所有旧调用，网络层拒绝AIsa和未批准域名；测试拦截负例必须确实失败。
包含强制周任务、复盘时间推进和可选集成路径。脱敏日志覆盖异步、线程、子进程，不记录Authorization或带Key的查询URL。

### T4 真实数据与模型

35账号、30个X搜索、50个SEO词、20个新站案例、20个Reddit查询、20个视频；各来源单独先跑小样本再扩大。
同窗对照尽量相隔≤5分钟；记录翻页和缺失，所有失败样本进入分母，避免幸存者偏差。
人工名字标签至少200条、用途/需求证据至少100组；保留验收集不用于调prompt，每组重复3次并报告最差结果。
具体精确率/召回率/曲线一致性及跨源差异阈值，以验收标准冻结版本为准。

### T5 稳定性与费用

7天14轮影子运行，使用独立state和报告目录，不向正式任务写入。
故障注入覆盖重启、限流、费用未知、并发竞争、免费额度耗尽及任务轮询中断。
用后台账单与客户端usage核对，分别报告现金支出、试用折扣和长期常规价格；月成本由实际工作量外推并列出假设。
降本目标不固定为50%；在不降低质量的前提下尽可能降低，最终目标由实测和用户预算冻结。

## 8. 证据、变更与退出条件

私有证据放在已忽略的`state/acceptance/`，避免将密钥、帖子原文或供应商受限数据提交Git。

遇到这些条件可继续无依赖的离线工作，但不得跳过该门并宣称完整交付。
